## 1. Общая структура

```json
{
  "parser_name":     "Название парсера",
  "version":         "1.0",
  "csv_columns":     ["поле1", "поле2", "поле3"],

  "max_distance":    1,
  "require_first_char": true,
  "stop_words":      [],
  "log_suspicious":  false,
  "debug_logging":   false,
  "process_timeout": 60,

  "tokenizer":       { "split_by": "whitespace" },
  "dedup":           { "key": "поле1" },
  "record_detection": { ... },
  "triggers":        { ... },
  "tests":           [ ... ]
}
```

**Обязательные поля:** `parser_name`, `csv_columns`, `triggers`.  
Все остальные — опциональные, имеют разумные значения по умолчанию.

## 2. Корневые параметры

### `parser_name` (string, обязательный)

Название парсера. Отображается в интерфейсе.

```json
"parser_name": "Реестр ячеек хранения"
```

---

### `version` (string)

Версия конфига. Используется для отслеживания изменений.

```json
"version": "1.2"
```

---

### `csv_columns` (array, обязательный)

Список имён колонок в выходном CSV/JSON/Excel. Порядок определяет порядок колонок в файле.

```json
"csv_columns": ["id", "номер", "владелец", "адрес", "документ"]
```

> **Важно:** если триггер пишет в колонку через `csv_column`, это имя должно быть в `csv_columns`.

---

### `max_distance` (int, по умолч. 1)

Максимальное расстояние Левенштейна при fuzzy-поиске триггера.  
При `max_distance: 1` слово с одной опечаткой всё равно будет распознано.

```json
"max_distance": 1
```

| Значение | Поведение |
|----------|-----------|
| `0` | Только точное совпадение (быстрее) |
| `1` | Одна опечатка / пропущенная буква (рекомендуется) |
| `2` | Две опечатки (риск ложных срабатываний) |

**Пример:** при `max_distance: 1` слово `"Фиo."` (латинская o) будет распознано как триггер `"фио"`.

---

### `require_first_char` (bool, по умолч. true)

Если `true` — при fuzzy-поиске сравниваются только алиасы, у которых совпадает первый символ с токеном. Значительно снижает риск ложных срабатываний.

```json
"require_first_char": true
```

**Пример:** с `true` слово `"Адр."` не будет сравниваться с триггером `"фио"` (разные первые буквы).

---

### `log_suspicious` (bool, по умолч. false)

Собирать ли токены, которые не попали ни в одно поле. При включении на вкладке
«Результаты» появляется секция «Потерянные токены» с частотой каждого токена.

```json
"log_suspicious": true
```

> **Что считается потерянным:** токен считается потерянным только если в момент
> его обработки нет открытого поля (`current_field is None`). Если поле открыто —
> токен добавляется к его значению, это нормальное поведение, а не потеря.
> Константа `MAX_SUSPICIOUS_SHOWN = 50` ограничивает число токенов в отображении.

> **Тип данных:** внутри движка `suspicious_log` — это `Counter` (не `set`),
> поэтому для каждого потерянного токена хранится количество вхождений.
> В интерфейсе это отображается как `токен ×N`.

---

### `debug_logging` (bool, по умолч. false)

Включить пошаговый лог парсинга. При включении каждый токен протоколируется.  
**Не включайте на продакшене** — сильно замедляет обработку больших файлов.

```json
"debug_logging": false
```

---

### `process_timeout` (int, по умолч. 60)

Максимальное время обработки одного запроса в секундах.  
При превышении сервер вернёт ошибку 503.

```json
"process_timeout": 120
```

> **Реализация:** обработка файлов запускается в `ThreadPoolExecutor` с таймаутом.
> При превышении — `503 Service Unavailable` с понятным сообщением.

---

### `tokenizer` (object)

Настройки разбиения текста на токены.

```json
"tokenizer": {
  "split_by": "whitespace"
}
```

| `split_by` | Поведение |
|------------|-----------|
| `"whitespace"` | Разбивать только по пробелам (по умолчанию) |
| `"whitespace_and_punctuation"` | Также разбивать по знакам пунктуации |

**Когда использовать `whitespace_and_punctuation`:** если в тексте значения разделены запятыми без пробелов, например `"Иванов,Иван,Иванович"`.

## 2а. Базовая аутентификация

Управляется переменными окружения при запуске — **не задаётся в конфиге**.

```bash
TRIGGERPARSE_USER=admin TRIGGERPARSE_PASS=secret python engine_web.py
```

| Переменная | Описание |
|------------|----------|
| `TRIGGERPARSE_USER` | Логин |
| `TRIGGERPARSE_PASS` | Пароль |

Если обе переменные не заданы — сервер работает без авторизации (как раньше).
При включении все маршруты (`/`, `/analyze`, `/debug`, `/upload_config` и др.)
требуют HTTP Basic Auth. Браузер показывает стандартное окно ввода.

> **Безопасность:** используйте аутентификацию если сервер доступен не только
> с `localhost`. Для публичного доступа рекомендуется дополнительно настроить
> HTTPS через reverse proxy (nginx, Caddy).

## 3. Сегментация на записи

`record_detection` определяет как разбить весь текст на отдельные записи перед парсингом.

```json
"record_detection": {
  "mode":    "trigger",
  "trigger": "яч",
  "continuation_heuristics": {
    "detect_by":            "has_letter | starts_upper",
    "max_tokens_to_check":  5
  }
}
```

### Поля

| Поле | Тип | Описание |
|------|-----|----------|
| `mode` | string | Всегда `"trigger"` |
| `trigger` | string | Имя триггера, с которого начинается новая запись |
| `continuation_heuristics` | object | Правило слияния с предыдущей записью |

### `continuation_heuristics`

Иногда запись физически разделена на несколько строк без повторения триггера. Хевристика определяет, нужно ли текущий сегмент **присоединить** к предыдущей записи.

```json
"continuation_heuristics": {
  "detect_by":           "has_letter",
  "max_tokens_to_check": 3
}
```

Движок проверяет первые `max_tokens_to_check` токенов нового сегмента. Если предикат `detect_by` возвращает `true` **и** сегмент не начинается с самого триггера — сегмент присоединяется к предыдущей записи.

> **Важно:** сегмент **никогда** не присоединяется если его первый токен — сам триггер начала записи (защита от схлопывания всех записей в одну).

## 4. Триггеры

Триггер — это ключевое слово в тексте, которое открывает поле для сбора значения.

```json
"triggers": {
  "имя_триггера": {
    "aliases":     ["кад", "кадастр", "кн"],
    "search_mode": "fuzzy",
    "csv_column":  "кадастр",
    ...
  }
}
```

### `aliases` (array, обязательный)

Список вариантов написания триггерного слова. Движок ищет любой из них в тексте.

```json
"aliases": ["фио", "ф.и.о", "фамилия"]
```

---

### `search_mode` (string, обязательный)

| Режим | Поведение | Когда использовать |
|-------|-----------|---------------------|
| `"fuzzy"` | Сравнение с расстоянием Левенштейна | Слова с возможными опечатками |
| `"exact"` | Точное совпадение | Короткие однозначные метки |
| `"regex"` | Первый алиас — регулярное выражение | Числа, коды, форматированные строки |

**Пример fuzzy:**
```json
"aliases": ["ном", "номер"],
"search_mode": "fuzzy"
```
Найдёт: `"Ном."`, `"НОМ"`, `"Номер."`, `"Нoмер"` (одна опечатка).

**Пример exact:**
```json
"aliases": ["ID", "id"],
"search_mode": "exact"
```
Найдёт только точное `"ID"` или `"id"`, без отклонений.

**Пример regex:**
```json
"aliases": ["^\\d{2}\\.\\d{2}\\.\\d+$"],
"search_mode": "regex"
```
Найдёт токены вида `"59.34"`, `"12.08"` — числа через точку.

---

### `csv_column` (string, по умолч. имя триггера)

Имя колонки CSV, в которую записывается значение. Позволяет нескольким триггерам писать в одну колонку.

```json
"фио": { "csv_column": "владелец", ... },
"орг": { "csv_column": "владелец", ... }
```

Оба триггера `"фио"` и `"орг"` будут писать в колонку `"владелец"`.

---

### `on_new_record` (bool, по умолч. false)

Если `true` — при встрече этого триггера начинается **новая запись** (старая сохраняется).  
Обычно устанавливается на тот же триггер, что указан в `record_detection.trigger`.

```json
"яч": {
  "aliases":       ["яч"],
  "search_mode":   "fuzzy",
  "on_new_record": true,
  ...
}
```

## 5. Нормализация

После того как значение поля собрано, оно прогоняется через цепочку шагов нормализации.

```json
"normalization": {
  "pipeline": ["strip", "remove_trailing_dot", "collapse_spaces"]
}
```

Шаги применяются **последовательно** — результат каждого передаётся следующему.

### Базовые шаги

| Шаг | Что делает | Пример |
|-----|-----------|--------|
| `strip` | Убрать пробелы по краям | `" текст "` → `"текст"` |
| `collapse_spaces` | Схлопнуть множественные пробелы | `"а  б   в"` → `"а б в"` |
| `remove_dots` | Удалить все точки | `"И.И.Иванов"` → `"ИИИванов"` |
| `remove_trailing_dot` | Удалить точку в конце | `"418.4."` → `"418.4"` |
| `remove_spaces` | Удалить все пробелы | `"5 9 : 3 4"` → `"59:34"` |
| `uppercase` | К верхнему регистру | `"москва"` → `"МОСКВА"` |
| `lowercase` | К нижнему регистру | `"МОСКВА"` → `"москва"` |
| `digits_only` | Только цифры | `"Яч. 5а"` → `"5"` |

---

### Замена символов: `replace_char`

Универсальная замена одного символа на другой. Синтаксис: `replace_char:ЧТО->НА_ЧТО`.

```json
"pipeline": ["replace_char:.->:"]
```

`"59.34.640098"` → `"59:34:640098"`

Для замены **только внутри слова** (не в начале и конце):

```json
"pipeline": ["replace_char:internal:.>/"]
```

`"418.4"` → `"418/4"` (точка между цифрами заменяется на `/`)

> **Разделитель `->` не конфликтует с `:` в именах символов**, в отличие от старого синтаксиса.

---

### Работа с адресами: `replace_dot_*` и `replace_space_*`

Специальные шаги для разбора адресных строк.

**`replace_dot_before_keywords:kw1,kw2,...`**  
Заменяет точку **перед** ключевым словом на запятую.

```json
"replace_dot_before_keywords:улица,дом,город,область,край"
```

`"Ленинградская область. Город Краснодар. Улица Гагарина."` → `"Ленинградская область, Город Краснодар, Улица Гагарина."`

**`replace_dot_after_keywords:kw1,kw2,...`**  
Убирает точку **после** ключевого слова.

```json
"replace_dot_after_keywords:дом,улица,город"
```

`"Молодежный дом. 173"` → `"Молодежный дом 173"`

**`replace_space_before_keywords:kw1,kw2,...`**  
Заменяет пробел **перед** ключевым словом на `", "` и капитализирует следующее слово.  
Для случаев когда ключевое слово стоит после значения без разделяющей точки.

```json
"replace_space_before_keywords:дом,улица,проспект"
```

`"Молодежный дом 173"` → `"Молодежный, Дом 173"`

**Рекомендуемый пайплайн для адресного поля:**

```json
"pipeline": [
  "strip",
  "replace_dot_before_keywords:улица,дом,город,область,край,район,проспект,бульвар,переулок",
  "replace_dot_after_keywords:улица,дом,город,область,край,район,проспект,бульвар,переулок",
  "replace_space_before_keywords:дом,улица,проспект,бульвар,переулок",
  "remove_dots",
  "collapse_spaces"
]
```

---

### Числовая нормализация

**`normalize_number[:decimal_sep[:thousand_sep]]`**  
Приводит число к стандартному виду с точкой.

```json
"pipeline": ["normalize_number:,:"]
```

| Входной формат | Параметры | Результат |
|----------------|-----------|-----------|
| `"1 234,56"` | `normalize_number:,:` | `"1234.56"` |
| `"1.234,56"` | `normalize_number:,:.` | `"1234.56"` |
| `"3.14"` | `normalize_number` | `"3.14"` (без изменений) |

**`to_int`** — оставить только целую часть:
```json
"pipeline": ["to_int"]
```
`"418.4"` → `"418"`

**`to_float:N`** — округлить до N знаков:
```json
"pipeline": ["to_float:2"]
```
`"3.14159"` → `"3.14"`, при `to_float:0` → `"3"`

**`pad_left:N[:символ]`** — дополнить слева до длины N:
```json
"pipeline": ["pad_left:6"]
```
`"42"` → `"000042"`

**`pad_right:N[:символ]`** — дополнить справа:
```json
"pipeline": ["pad_right:4:0"]
```
`"12"` → `"1200"`

---

### Словарные замены: `apply_replacements`

Применяет словарь `replacements` из конфига триггера.

```json
"dok": {
  "normalization": {
    "pipeline": ["strip", "apply_replacements", "collapse_spaces"]
  },
  "replacements": {
    "Выписка и ГРН":          "Выписка ЕГРН",
    "Акт приема и передачи":  "Акт приема-передачи",
    "Ак приема и передачи":   "Акт приема-передачи"
  }
}
```

---

### Произвольная замена: `regex_sub`

```json
"pipeline": ["regex_sub:\\s+->_"]
```

`"Иван Иванов"` → `"Иван_Иванов"` (пробелы заменены на `_`)

## 6. Валидация

Проверяет нормализованное значение. При несоответствии добавляет код ошибки в поле `err`.

```json
"validation": {
  "rule":       "word_count:2,3",
  "error_code": "errFIO2"
}
```

### Правила

| Правило | Пример | Проходит | Не проходит |
|---------|--------|----------|-------------|
| `not_empty` | `"not_empty"` | любая непустая строка | `""` |
| `word_count:min,max` | `"word_count:2,3"` | `"Иванов Иван"` | `"Иванов"` (1 слово) |
| `regex:ПАТТЕРН` | `"regex:^[0-9:]+$"` | `"59:34:640098"` | `"59.34abc"` |

**Пример для кадастрового номера:**
```json
"validation": {
  "rule":       "regex:^[0-9А-ЯЁ:]+$",
  "error_code": "errKAD2"
}
```

## 7. Коллектор

Собирает несколько токенов после триггера в одно значение.

```json
"collector": {
  "token_rule": "starts_upper",
  "max_tokens": 3
}
```

### Поля

| Поле | Тип | Описание |
|------|-----|----------|
| `token_rule` | предикат | Условие приёма токена |
| `max_tokens` | int | Максимальное количество токенов |

**Как работает:** после открытия поля коллектор поглощает токены, пока:
- `token_rule(токен) == true`
- счётчик не превысил `max_tokens`
- не встретился явный триггер (защита от поглощения следующего поля)

**Пример — сбор ФИО (до 3 слов с заглавной буквы):**
```json
"фио": {
  "aliases":   ["фио"],
  "search_mode": "fuzzy",
  "csv_column": "владелец",
  "collector": {
    "token_rule": "starts_upper",
    "max_tokens": 3
  }
}
```

Текст: `"Фио. Смирнов. Николай. Евгеньевич."`  
Результат: `владелец = "Смирнов Николай Евгеньевич"`

**Пример — сбор ровно одного значения (номер ячейки):**
```json
"яч": {
  "collector": { "token_rule": "any", "max_tokens": 1 }
}
```

## 8. Многотокенное поле

Используется для полей, значение которых состоит из нескольких токенов определённого формата (кадастровый номер, артикул, код).

```json
"multi_token": {
  "enabled":    true,
  "token_rule": "is_part_of_number_colon_dot"
}
```

### Отличие от `collector`

| | `collector` | `multi_token` |
|--|-------------|---------------|
| Когда активен | Сразу после открытия поля | Всё время пока поле открыто |
| Прерывается | По лимиту или по правилу | Когда правило не выполняется |
| Типичное использование | ФИО, организация | Кадастровый номер, серийный код |

**Пример — кадастровый номер:**
```json
"кад": {
  "aliases":   ["кад", "кадастр", "кн", "када"],
  "search_mode": "fuzzy",
  "multi_token": {
    "enabled":    true,
    "token_rule": "is_part_of_number_colon_dot"
  },
  "normalization": {
    "pipeline": ["strip", "remove_trailing_dot", "replace_char:.->:", "uppercase", "remove_spaces"]
  }
}
```

Текст: `"Кад. 59.34. 640098. 498."` → кадастр `"59:34:640098:498"`

Движок продолжает собирать токены пока они похожи на части числового кода. Как только встречается буквенный токен — поле закрывается.

## 9. Эвристики

Эвристика позволяет открыть поле **без явного триггера**, если токен соответствует определённому паттерну и контекст подходящий.

```json
"heuristics": {
  "priority":        10,
  "if_missing_after": "ном",
  "detect_by":       "starts_upper",
  "unless":          "looks_like_number_colon_dot",
  "error_code":      "errFIO1"
}
```

### Поля

| Поле | Тип | Описание |
|------|-----|----------|
| `priority` | int | Порядок проверки (меньше = раньше). По умолч. 100 |
| `if_missing_after` | string | Срабатывает только если текущее поле = указанному |
| `detect_by` | предикат | Условие срабатывания на токен |
| `unless` | предикат | Исключение: если `true` — эвристика НЕ срабатывает |
| `error_code` | string | Код ошибки, добавляемый при срабатывании |

### Логика работы

```
Если текущее поле == if_missing_after
И токен соответствует detect_by
И токен НЕ соответствует unless
→ открываем это поле с кодом ошибки error_code
```

**Пример 1 — ФИО без слова-триггера:**  
В тексте: `"Ном. 418.4. Смирнов. Николай. Евгеньевич."` — слово `"Фио"` пропущено.

```json
"фио": {
  "heuristics": {
    "priority":        10,
    "if_missing_after": "ном",
    "detect_by":       "starts_upper",
    "error_code":      "errFIO1"
  }
}
```

После поля `ном` встречается токен `"Смирнов."` (с заглавной) — открывается поле `фио` с ошибкой `errFIO1`.

**Пример 2 — адрес без слова-триггера:**  
После кадастрового номера адрес может идти без слова `"Адр."`.

```json
"адр": {
  "heuristics": {
    "priority":        30,
    "if_missing_after": "кад",
    "detect_by":       "has_letter",
    "error_code":      "errADR1"
  }
}
```

**Пример 3 — исключение через `unless`:**  
Организация (не ФИО) — любой токен после `ном`, кроме заглавных слов и чисел:

```json
"орг": {
  "heuristics": {
    "priority":        20,
    "if_missing_after": "ном",
    "unless":          "starts_upper | looks_like_number_colon_dot",
    "detect_by":       "any",
    "error_code":      "errORG1"
  }
}
```

### Priority — порядок эвристик

Если несколько эвристик могут сработать на один токен, побеждает та у которой меньше `priority`. Рекомендуемые значения:

```
фио:  priority: 10   (самая специфичная — только заглавные)
орг:  priority: 20   (менее специфичная — любые токены с исключениями)
адр:  priority: 30   (наиболее широкая)
```

## 10. Детектор дублей

Автоматически помечает повторяющиеся записи по значению ключевого поля.

```json
"dedup": {
  "key":            "яч",
  "error_code":     "errDUP",
  "case_sensitive": false
}
```

### Поля

| Поле | Тип | По умолч. | Описание |
|------|-----|-----------|----------|
| `key` | string | — | Поле-ключ для сравнения (обязательно) |
| `error_code` | string | `"errDUP"` | Код ошибки для дублей |
| `case_sensitive` | bool | `false` | Учитывать регистр при сравнении |

Первое вхождение — оригинал. Все последующие с тем же значением ключа получают `errDUP`.

```json
"dedup": {
  "key": "номер_договора",
  "error_code": "errDOUBLE"
}
```

## 10а. Распределение значений

После анализа на вкладке «Результаты» появляется секция **«Распределение значений по полям»** —
сетка карточек, по одной на каждую колонку из `csv_columns`.

Каждая карточка показывает:
- Количество уникальных значений и непустых записей (`N уник. / M запис.`)
- Список значений встречающихся **более одного раза** с частотой (`×N`)
- Если все значения уникальны — пометка «все значения уникальны»

**Зачем нужно:**
- В `dok` (тип документа) повторы нормальны — поле категориальное
- В `кад` (кадастровый номер) повтор — сигнал ошибки парсинга или исходных данных
- В `фио/орг` повтор — возможный дубль записи (перепроверьте через `dedup`)

Данные берутся из поля `value_distribution` в объекте статистики который возвращает
`compute_stats()`. Структура:

```python
stats["value_distribution"]["dok"] == {
    "unique":         2,       # уникальных значений
    "filled":         10,      # всего непустых записей
    "repeated":       [("Паспорт", 6), ("Договор", 4)],  # топ повторяющихся
    "repeated_total": 2,       # сколько всего значений повторяется > 1 раза
}
```

Константа `MAX_VALUE_DIST_SHOWN = 8` ограничивает число отображаемых повторов.

## 11. Стоп-слова

Стоп-слово — токен, который выбрасывается из текста. Используется для удаления служебных слов, которые мешают парсингу.

### Глобальные стоп-слова

Применяются ко всему тексту независимо от поля.

```json
"stop_words": ["дома", "дому", "доме", "домов"]
```

> **Внимание:** не добавляйте в `stop_words` слова, которые могут быть частью значений полей. Например, слово `"дом"` лучше убрать из стоп-слов и обработать через нормализацию адреса.

### Стоп-слова на уровне триггера

Дополняют глобальные, действуют только когда данное поле открыто.

```json
"адр": {
  "stop_words":      ["корп", "корпус"],
  "stop_word_error": "errADR_STOP"
}
```

При срабатывании добавляет `stop_word_error` вместо стандартного `errSTOP`.

## 12. Предикаты

Предикаты используются в `detect_by`, `unless`, `token_rule`, `continuation_heuristics.detect_by`.

| Предикат | Описание | Примеры токенов (true) |
|----------|----------|------------------------|
| `starts_upper` | Начинается с заглавной буквы (не цифра) | `"Смирнов."`, `"Москва"` |
| `has_letter` | Содержит хотя бы одну букву | `"418а"`, `"Город"`, `"ул."` |
| `looks_like_number_colon_dot` | Только цифры, буквы, точки, двоеточия | `"59.34"`, `"АА:123"` |
| `is_part_of_number_colon_dot` | То же + содержит цифру или точку/двоеточие | `"59.34"` (но не `"АА"`) |
| `any` | Любой непустой токен | всё кроме `""` |
| `regex:ПАТТЕРН` | Совпадение с регулярным выражением | зависит от паттерна |

### Комбинирование через `|`

```json
"detect_by": "starts_upper | looks_like_number_colon_dot"
```

Срабатывает если токен соответствует **хотя бы одному** из условий (логическое ИЛИ).

### Примеры предикатов

**Только заглавные слова-фамилии:**
```json
"detect_by": "starts_upper"
```

**Любой буквенный контент (для адреса):**
```json
"detect_by": "has_letter"
```

**Числовой код (для кадастра без триггера):**
```json
"detect_by": "looks_like_number_colon_dot"
```

**Произвольный формат — дата:**
```json
"detect_by": "regex:\\d{2}\\.\\d{2}\\.\\d{4}"
```

## 13. Тест-кейсы

Секция `tests` позволяет задать ожидаемые результаты парсинга и запускать их через вкладку «Тесты» в интерфейсе.

```json
"tests": [
  {
    "description":   "Базовый тест — ФИО",
    "input":         "Яч 1. Ном. 418.4. Фио. Смирнов. Николай. Евгеньевич.",
    "expect": {
      "яч":     "1",
      "ном":    "418/4",
      "фио/орг": "Смирнов Николай Евгеньевич"
    }
  },
  {
    "description":   "Организация вместо ФИО",
    "input":         "Яч 3. Ном. 434.2. орг. ООО Арболит.",
    "expect": {
      "яч":     "3",
      "фио/орг": "ООО Арболит"
    }
  },
  {
    "description":   "ФИО без триггера (эвристика)",
    "input":         "Яч 9. Ном. 101.8. Морозов. Андрей. Андреевич.",
    "expect_record": 0,
    "expect": {
      "яч":     "9",
      "фио/орг": "Морозов Андрей Андреевич",
      "err":    "errFIO1"
    }
  }
]
```

### Поля тест-кейса

| Поле | Тип | Описание |
|------|-----|----------|
| `description` | string | Название теста (отображается в результатах) |
| `input` | string | Входной текст для парсинга |
| `expect` | object | Словарь `{поле: ожидаемое_значение}` |
| `expect_record` | int | Индекс записи для проверки (по умолч. `0`) |

> **Совет:** начинайте с простых тестов и постепенно добавляйте граничные случаи. При изменении конфига запускайте тесты чтобы убедиться что ничего не сломалось.

## 15. Коды ошибок

Ошибки записываются в колонку `err` через точку с запятой. Поле остаётся пустым если ошибок нет.

| Код | Источник | Значение |
|-----|----------|----------|
| `errSTOP` | Глобальное стоп-слово | В тексте встретилось стоп-слово |
| `errDUP` | Детектор дублей | Запись с таким ключом уже встречалась |
| `errFIO1` | `heuristics.error_code` | ФИО распознано без триггера |
| `errFIO2` | `validation.error_code` | ФИО не прошло валидацию (не 2-3 слова) |
| `errKAD2` | `validation.error_code` | Кадастровый номер содержит недопустимые символы |
| `errADR1` | `heuristics.error_code` | Адрес распознан без триггера |
| `errORG1` | `heuristics.error_code` | Организация распознана без триггера |

Коды ошибок задаются в конфиге — вы можете использовать любые строки.

## 16. Советы и типичные ошибки

### ✅ Рекомендации

**1. Всегда начинайте с тестов.**  
Добавьте 3–5 типичных входных строк в секцию `tests` до того как начнёте тонко настраивать конфиг. Это страховка при изменениях.

**2. Используйте отладку для диагностики.**  
Вкладка «Отладка» → фильтр «LOST» покажет токены которые теряются. Фильтр «HEUR» — где срабатывают эвристики.

**3. `priority` у эвристик — не опция, а правило.**  
Всегда явно задавайте `priority`. Без него порядок зависит от порядка ключей в JSON, что непредсказуемо при редактировании.

**4. Не кладите в `stop_words` слова, которые нужны для нормализации.**  
Стоп-слово выбрасывается ДО нормализации. Если слово нужно в адресе — обрабатывайте его через `replace_dot_after_keywords`.

**4а. Debug-лог автоматически обрезается.**  
При включённом `"debug_logging": true` лог ограничен `MAX_DEBUG_LOG_LINES = 20000` строк.
После достижения лимита добавляется маркер усечения и дальнейшие строки отбрасываются.
Это защищает от перерасхода памяти на больших файлах.

**5. `collector` с `max_tokens: 1` для однозначных полей.**  
Если поле всегда содержит ровно одно значение (номер ячейки, порядковый номер) — используйте коллектор с лимитом 1. Это предотвращает случайное поглощение следующих токенов.

**6. `csv_column` позволяет объединять триггеры.**  
Если у вас есть поля "физическое лицо" и "юридическое лицо" которые взаимно исключают друг друга — направьте оба в одну колонку через `csv_column`.

### ❌ Типичные ошибки

**Ошибка: `"4/1/8/./4"` вместо `"418/4"`**  
Причина: в шаге `replace_char:internal:->/ ` потеряна точка — написано `replace_char:internal:->/` вместо `replace_char:internal:.->/`.  
Синтаксис: `replace_char:internal:ЧТО->НА_ЧТО`.

**Ошибка: все записи сливаются в одну**  
Причина: `continuation_heuristics.detect_by` слишком широкий предикат, срабатывает на первый токен каждой новой записи.  
Решение: движок автоматически защищает от этого — сегмент не сливается если начинается с триггера начала записи.

**Ошибка: поле `фио/орг` пустое в CSV**  
Причина: триггеры `фио` и `орг` не имеют `"csv_column": "фио/орг"`.  
Решение: явно укажите `csv_column` для каждого триггера.

**Ошибка: эвристика срабатывает в неожиданный момент**  
Причина: `if_missing_after` не задан — эвристика проверяется для любого текущего поля.  
Решение: всегда задавайте `if_missing_after` для точного контроля контекста.

**Ошибка: кадастровый номер разбит на части**  
Причина: `multi_token` не настроен, поле закрывается после первого токена.  
Решение: добавьте `"multi_token": {"enabled": true, "token_rule": "is_part_of_number_colon_dot"}`.

**Ошибка: `"дом"` исчезает из адреса**  
Причина: `"дом"` в глобальных `stop_words`.  
Решение: уберите `"дом"` из `stop_words` и добавьте шаги `replace_dot_after_keywords` и `replace_space_before_keywords` в пайплайн адреса.
