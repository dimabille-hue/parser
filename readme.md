# TriggerParse Engine

Универсальный конфигурируемый парсер неструктурированного текста с веб-интерфейсом.

Превращает текстовые документы вида *«Яч 1. Ном. 418.4. Фио. Смирнов. Николай
Евгеньевич. Када. 59.34.640098.498. Адр. Москва. Dok. Паспорт.»* в структурированные
таблицы (CSV / JSON / Excel) — без единой строки кода. Вся логика распознавания
полей, нормализации значений и обработки ошибок описывается JSON-конфигом.

---

## Возможности

- **Триггерный парсинг** — поля распознаются по ключевым словам с fuzzy-поиском
  (опечатки, разные падежи, сокращения)
- **Эвристики** — поля без явного триггера распознаются по контексту и формату
  значения (с приоритетами и логированием как ошибка)
- **Гибкая нормализация** — более 15 встроенных шагов: замена символов, работа
  с адресами, числовые форматы, словарные замены, регулярные выражения
- **Сегментация записей** — текст автоматически разбивается на отдельные записи
  по триггеру начала записи, с защитой от схлопывания в одну гигантскую запись
- **Детектор дублей** — повторяющиеся записи помечаются автоматически
- **Веб-интерфейс** — загрузка файлов, live-валидация конфига, интерактивная
  отладка по токенам, статистика, предпросмотр результатов
- **Экспорт** — CSV, JSON, Excel (с подсветкой ошибок)
- **Встроенный тест-раннер** — регрессионные тесты конфига прямо в браузере
- **Автоопределение кодировки** — UTF-8, UTF-8 BOM, CP1251, с опциональным `chardet`

## Требования

- Python **3.10+** (используется синтаксис `list[str]`, `dict | None`)
- Без обязательных внешних зависимостей — работает на чистом `stdlib`

### Опциональные зависимости

| Пакет | Зачем нужен | Без него |
|-------|-------------|----------|
| `openpyxl` | Экспорт в Excel (`.xlsx`) | Кнопка «Excel» вернёт `501`, CSV и JSON работают |
| `chardet` | Более точное автоопределение кодировки | Используется цепочка `utf-8-sig → utf-8 → cp1251 → latin-1` |

```bash
pip install openpyxl chardet
```

## Быстрый старт

```bash
python engine_web.py [порт]
```

По умолчанию порт `8000`. Открыть в браузере:

```
http://localhost:8000
```

При старте сервер пытается загрузить `default_config.json` из текущей директории.
Если файла нет — загрузите конфиг через вкладку **«Конфигурация»** в интерфейсе
(он автоматически сохранится как `default_config.json` для следующих запусков).

### Базовая аутентификация (опционально)

По умолчанию сервер открыт без авторизации. Чтобы включить HTTP Basic Auth:

```bash
TRIGGERPARSE_USER=admin TRIGGERPARSE_PASS=secret python engine_web.py
```

Браузер запросит логин/пароль при первом обращении. Если переменные не заданы —
доступ открыт всем.

## Интерфейс

Веб-интерфейс состоит из пяти вкладок:

| Вкладка | Назначение |
|---------|------------|
| **Основное** | Загрузка TXT-файлов, запуск анализа, скачивание CSV |
| **Результаты** | Статистика, заполненность полей, топ-ошибок, распределение значений, предпросмотр таблицы, экспорт CSV/JSON/Excel |
| **Конфигурация** | Загрузка/редактирование JSON-конфига с live-валидацией, скачивание текущего конфига |
| **Отладка** | Пошаговый интерактивный лог парсинга — фильтры по типу события, поиск, раскрываемые записи |
| **Тесты** | Запуск регрессионных тест-кейсов из секции `tests` конфига |

Документация по составлению конфига доступна прямо в интерфейсе по ссылке
**«📖 Документация»** (`/docs`) — генерируется из кода, всегда актуальна.

## Конфигурация

Минимальный конфиг:

```json
{
  "parser_name": "Мой парсер",
  "csv_columns": ["поле1", "поле2"],
  "triggers": {
    "поле1": {
      "aliases": ["метка1"],
      "search_mode": "fuzzy",
      "collector": { "token_rule": "any", "max_tokens": 1 }
    },
    "поле2": {
      "aliases": ["метка2"],
      "search_mode": "fuzzy"
    }
  }
}
```

Полное руководство со всеми параметрами, примерами и типичными ошибками —
в [`CONFIG_GUIDE.md`](CONFIG_GUIDE.md).

## API-маршруты

| Маршрут | Метод | Описание |
|---------|-------|----------|
| `/` | GET | Главная страница |
| `/analyze` | POST | Анализ файлов → страница результатов |
| `/debug` | POST | Анализ с пошаговым логом → страница отладки |
| `/upload_config` | POST | Загрузка нового конфига |
| `/validate_config` | POST | Live-валидация JSON (используется интерфейсом) |
| `/run_tests` | GET | Запуск тест-кейсов из конфига |
| `/download/<token>?fmt=csv\|json\|xlsx` | GET | Скачивание результатов анализа |
| `/download_config` | GET | Скачивание текущего конфига |
| `/debug_log/<name>` | GET | Скачивание raw debug-лога |
| `/progress` | GET | SSE-стрим прогресса обработки |
| `/docs` | GET | Документация конфига |

## Ограничения и лимиты

| Параметр | Значение | Где настраивается |
|----------|----------|--------------------|
| Максимальный размер загружаемого файла | 32 МБ | `MAX_UPLOAD_BYTES` в коде |
| Таймаут обработки запроса | 60 сек | `process_timeout` в конфиге |
| Максимум строк debug-лога | 20 000 | `MAX_DEBUG_LOG_LINES` в коде |
| Предпросмотр результатов | первые 50 записей | `_handle_analyze` в коде |

---

## Логирование

Логи пишутся в консоль (уровень INFO) и в файл `engine.log` с ротацией
(5 МБ × 3 файла, уровень DEBUG). HTTP-запросы логируются на уровне DEBUG.
